I think we’re actually starting to build something that looks like a real company now. 

Not just a bunch of virtual machines sitting around.

Earlier, I created the departmental folders on my dedicated company data disk and set up security groups in Active Directory.

The next question was...👀

Who should actually be allowed to access these folders, and what should they be allowed to do?

So I started with NTFS permissions.

Engineering gets access to Engineering.
HR gets access to HR.
Management gets access to Management.

Not because I manually gave individual users access, but because access is tied to their security groups.

That difference matters alot.

Because in a real organization, you don't want to manage permissions for hundreds of employees one person at a time.

You manage the groups where the users are in.

The next was....👀🚀

SMB (Server Message Block).

The folders existed on the Windows Server, but they weren't yet available to other computers on the network.

So I configured them as SMB shares.

Now the Engineering folder could be accessed across the network rather than existing only on the server.

And this is where Ubuntu came in.

My Ubuntu VM became the client, essentially acting like an employee's workstation trying to access company resources from the network.

At this point, I'm no longer testing isolated configurations.

I'm testing a chain:

Identity → Group → NTFS Permission → SMB → Network Client

And one of the most important infrastructure concepts became very clear:

Authentication ≠ Authorization.

Authentication asks:

“Who are you?" 👌

Authorization asks:

“What are you allowed to access?” 👌

You can successfully authenticate to a network and still be denied access to a resource.

That is the kind of thinking I'm beginning to appreciate about infrastructure engineering.

We are building. 🚀
