A few days ago, David Heinemeier Hansson opened the Rails World config with a really interesting talk: We do not need to write code by hand anymore. My X timeline went up in flames with a mixed bag of reactions. We spent decades turning code into a craft, a career, and, for some of us, a whole personality.

The weird thing is that I get it. I barely write code by hand anymore. For the past 8 or 9 months, Claude Code and Codex have been open on my computer all day. My job mostly turned into giving agents a problem, context, constraints, and direction. They implement the thing, I review it, yap a lot when they get things wrong, correct the course, and move on. I'm still in charge of the architecture decisions, I still decide what is good enough. And when things go bust in prod, I'm still the one getting paged to fix it.

The other weird thing is that we need more software than ever before. Software has always been expensive, so we learned to ignore thousands of problems that were not worth the engineering time. Small internal tool? Do it manually. Weird feature for ten customers? Go to a backlog ticket and wait for years. If the cost of building software drops, the number of things worth building goes up. We may write less code ourselves while producing more software than ever before.

This is the part that excites me. I feel like I was given an ironman suit, I can talk to Jarvis all day and get incredible things done. On the other hand, I'm still trying to figure out what comes next for engineers themselves.

A lot of us became senior engineers by breaking things. Bad database migrations, memory leaks, race conditions, production bugs, and weekend incident that permanently changed my relationship with the famous last words “this should be easy.” Those experiences were painful, but necessary to build engineering muscle.

Now imagine starting your career with agents that can write the code, inspect stack traces, fix your queries, update tests, and explain a bug. That is amazing for shipping software. But friction was also part of how we learned.
So how do we create the next generation of senior engineers when so much of that friction disappears? 

I honestly have no clue. I don't know what the new learning path looks like. I don't know which skills will become more important, which ones will fade, or what “senior engineer” even means in ten years.

But I do know that I want to be part of figuring it out. Software engineering is not disappearing. It is changing shape very quickly.

This moment feels both terrifying and exciting.
