Kestrel Leasing's support team was drowning in the same call, over and over — from drivers like Priya, three years into her lease, and Tomasz, who'd just signed:

"What's my mileage cap?"
"Can I end my lease early without a fee?"

Every answer was sitting in a contract the driver had already signed. Hold times: 20–40 minutes for a one-line answer. Same shape shows up for insurance policyholders, telecom customers — anywhere the answer already exists in a document the customer holds.

The fix was Amazon Bedrock Knowledge Bases — RAG (Retrieval-Augmented Generation). In plain terms: an open-book exam instead of closed-book. Look up the exact clause first, then answer — never from memory. The interesting part wasn't "add AI" — it was two decisions underneath it.

→ How do you split a 40-page lease into pieces a model can actually search?
"Chunking" isn't one thing — it's a family of strategies. Hierarchical for documents with real structure (sections, clauses): retrieves a precise clause, then hands back the full section for context. Semantic for documents where structure can't be trusted (scanned, OCR'd): splits by meaning instead, and costs more to run since it uses a model at ingestion time. Kestrel's real archive had both — this year's clean template, pre-2023 scanned contracts — so they used two strategies, routed by document type, into one searchable index, with a metadata filter making sure Priya's question never surfaces a clause from Tomasz's lease.

→ What actually gets a new lease into the system in the first place?
This is the part most write-ups skip. A file landing in S3 doesn't trigger anything by itself — StartIngestionJob is a manual API call, not a built-in auto-sync. The real fix: an S3 event or an EventBridge schedule triggers a small Lambda that calls the ingestion API for you. That's AWS's own documented pattern for closing this gap, not a built-in feature.

The lesson generalizes past leases: any RAG project built on "our real documents" needs to answer three things, not one — how documents get in, what wakes up the pipeline, and how the live question gets answered. Skipping the first two is how a demo works and production doesn't.
