What happens to a PLC programmer who keeps working exactly as before? 🤔

I gave Claude an electrical schematic and a description of how the plant should operate.
It configured the hardware in TIA Portal.

It wrote the PLC program.
Then it tested the program against my digital twin.
That is quite a lot of work I used to do myself.

And it makes me think about which skills we should be developing now.
👉 Defining what the machine should actually do.
👉 Giving AI agents the right information and context.
👉 Checking whether the program and the tests cover the real process.
👉 Taking responsibility for the result.

One task deserves more attention: making the right plant data accessible to AI.

Which data do we need?

How do we access them?

Through which interfaces and with which permissions?

That requires knowledge of the process, industrial communication and OT security.
The engineering knowledge still matters. I need it to recognise when Claude gets something wrong, when a test misses an important scenario or when the model doesn’t reflect the real machine.

But the work I do myself is changing.

If we continue to define our value mainly by how much PLC code we write manually, things could become uncomfortable pretty quickly.

Claude won’t wait for us to adapt. 🚀

How is your work already changing? And which skills are you investing in?
