Can We Stop Confusing Software Engineering With Writing Code? 😂

I'm tired of this endless debate.

"Is AI making developers lazy?"

"Can you still code without AI?"

"Are developers becoming prompt engineers instead of real engineers?"

We've been going in circles with these questions for years.

Frankly, I think we're asking the wrong questions.

“Software engineers are not glorified code typists.”

We analyze problems, design architectures, make trade-offs, manage complexity, define system behavior, investigate failures, address security risks, and deliver solutions that work.

Writing code is one part of that process. It was never the entire profession.

We've spent decades building compilers, frameworks, libraries, IDEs, automation, and sophisticated development tools.

Why?

TO REDUCE THE WORK HUMANS HAVE TO DO MANUALLY.

Now AI can generate code, and suddenly we're worried that developers might forget how to think?

Seriously? 😂

Some people even suggest occasionally building applications without AI just to prove we still can.

Should we also stop using frameworks? Write our own memory management? Give up debuggers? Maybe return to assembly language for the weekend?

And then there's my favorite argument:

"What happens when production crashes at 2 AM and AI can't save you?"

If your system regularly requires heroic debugging at 2 AM, perhaps you should question your architecture, resilience, monitoring, and operational practices instead of romanticizing firefighting.

“Engineering competence isn't measured by how much code you write or how much suffering you endure keeping it running.”

It's measured by your ability to understand problems, make sound decisions, build reliable systems, recognize failures, and verify outcomes.

AI doesn't excuse poor engineering. Neither does writing every line yourself.

Blindly accepting AI-generated code is irresponsible.

But so is blindly trusting human-written code.

Both require engineering discipline, testing, verification, and accountability.

And here's what really bothers me.

We're debating whether AI will turn developers into prompt writers while continuing to define developers as code writers.

That's the real intellectual trap.

AI isn't just changing how we code. It's giving us the opportunity to rethink how software is conceived, engineered, verified, operated, and evolved.

Yet we're still arguing about whether someone is a "real developer" if they don't manually type enough code.

It's 2026.

Can we move the conversation forward?

“The future of software engineering isn't about defending the act of writing code. It's about engineering better systems with the capabilities available to us.”

And if the only way you can demonstrate your engineering skills is by refusing to use modern tools, perhaps it's time to reconsider what you think engineering is. 😂
