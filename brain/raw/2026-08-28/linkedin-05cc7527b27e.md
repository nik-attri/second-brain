If you manage Time & Expenses or Usage-Based billing in Project Billing, here’s a change that reduces configuration effort and streamlines your billing process.What ChangedSince release 2602, you can create a billing document request (BDR) for billing elements even if no billing due date is defined. The system also creates the billing plan item at the same time. If no due date is set manually, the BDR creation date is used as the billing due date. This applies to Time and Expenses billing elements as well as Usage-Based billing elements.Now with release 2608, the feature toggle “Project Billing – Ad Hoc Billing (PROJ_BILLG_ADHOC_BILLG)” has been removed. The behavior is now automatically active in all customer systems — no toggle, no manual activation needed.Why It MattersThis change reduces configuration overhead by eliminating the need to coordinate feature activation post-upgrade, starting with release 2608. Project teams can now create BDRs immediately, even when a due date hasn’t been maintained, enabling faster billing cycles.Behavior DetailsWhen you create a BDR for an eligible billing element — either Time & Expenses or Usage-Based — the system checks whether a billing due date has been defined. If one exists, the system uses it. If no due date exists and you do not set one manually, the system automatically sets the billing due date to the BDR creation date. In both cases, the system also creates the corresponding billing plan item as part of the same process.Release Timeline RecapReleaseDetails2602 (initial delivery)Feature available but requires activation via the toggle “Project Billing – Ad Hoc Billing (PROJ_BILLG_ADHOC_BILLG)” in the “Activate Features” configuration activity.2608 (current change)Feature toggle removed. Behavior is automatically active post-upgrade; no customer action required. Example ScenarioA project’s Time & Expenses billing element has no due date configured. A billing specialist creates a BDR today. The system creates the related billing plan item and sets the billing due date to today’s date — unless the user specifies a different due date manually.FAQsDoes this change affect scope?No. The scope remains limited to Time & Expenses and Usage-Based billing elements.Can we still set a specific due date?Yes. You can manually set a due date. If you don’t, the system uses the BDR creation date.Is there any change in pricing, integrations, or downstream invoices?No functional changes beyond the automatic activation and the existing behavior when no due date is maintained. Key TakeawaysThe behavior introduced in 2602 remains unchanged. From release 2608, it is active by default — no feature toggle and no extra configuration steps are required. You can still set due dates manually whenever needed; if you do not, the system will use the BDR creation date as the billing due date.
