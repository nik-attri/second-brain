Before using Jenkins in a project, I wanted to understand one basic question:
👉 Why do we actually use Jenkins?

🔹 What is Jenkins?
Jenkins is an open-source automation server that helps automate software build, testing, and deployment. Instead of performing the same steps manually every time code changes, Jenkins can automate the workflow.

🔹 How does Jenkins fit into CI/CD?
A simple CI/CD flow looks like:

👨‍💻 Developer
↓
🐙 GitHub
↓
🔧 Jenkins
↓
📦 Build
↓
🧪 Test
↓
🚀 Deploy

This helped me understand that Jenkins is not just a tool for “running builds” it acts as an automation platform connecting different stages of software delivery.

🔹 Key Jenkins concepts I learned
⚙️ Controller : Manages Jenkins and pipeline execution
🖥️ Agent : Executes pipeline tasks
📁 Workspace : Where Jenkins works with project files
🔌 Plugins : Extend Jenkins functionality
🌐 Port 8080 : Default web interface port

🔹 Why Jenkins?
✅ Automates repetitive tasks
✅ Reduces manual effort
✅ Supports CI/CD
✅ Integrates with DevOps tools
✅ Makes the software delivery process more consistent

💡 My takeaway
Learning Jenkins made me realize that DevOps is not only about knowing individual tools.
It is about understanding how these tools work together to automate the complete software delivery process.

I’m continuing this journey step by step and sharing what I learn along the way. 🚀
