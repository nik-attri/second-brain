📅 Day 25 of #100DaysOfDevOps

What Is Kubernetes and Why Do We Need It? ☸️🚀

For the first 24 days, we explored Docker.

We learned how to build images, run containers, manage storage, networking, registries, security, and more.

But there's a problem when applications grow.

Imagine running 100 containers across multiple servers.

Who will:

Start failed containers?
Replace unhealthy containers?
Distribute workloads across servers?
Scale applications when traffic increases?
Perform rolling updates?
Keep the desired number of instances running?

Doing all of this manually quickly becomes difficult.

This is where Kubernetes comes in.

Kubernetes is an open-source container orchestration platform designed to automate the deployment, scaling, and management of containerized applications.

Think of Docker containers as cars 🚗.

Docker helps you build and run the cars.

Kubernetes is the traffic management system that manages thousands of cars across a large city.

It decides:

📍 Where workloads should run
🔄 When containers need to be replaced
📈 When applications need to scale
⚖️ How workloads should be distributed
🚀 How updates should be rolled out

For example, if your application should always have 3 running instances, Kubernetes continuously works to maintain that desired state.

If one instance fails:

3 desired → 2 running → Kubernetes creates another → 3 running
You don't have to manually SSH into a server and start another container.

That's the power of orchestration.

💡 Key Takeaway

Docker helps you run containers. Kubernetes helps you manage containers at scale.

Kubernetes doesn't replace the need to understand containers—it builds on those fundamentals.

And that's exactly where our journey goes next.
